# 场景行为（设计稿，未实施）

记录 2026-11-24 讨论的方向，等现有功能稳定后推进。这里写的都是计划，不是现状。

## 现状

- **联动**：物体关节按比例跟随同一物体内的另一个关节，写在 `usd_object.couplings`。
  由物理引擎保持（PhysX 的联动关节结构，Newton 和 OvPhysX 都生效），力双向传递。
- **运动**：实体的 `motion`，可选游走、沿路径、自定义函数（`shared/assembly/motion.py`）。
  只移动运动学实体或抽象体的位姿。
- **Task 的 `set`**：Task 发起、与任务语义相关的每步事件，作用于抽象体或运动学实体。

## 目标：都收拢成“关系”

每条关系由三部分组成：来源 → 规则 → 去向。

- **来源**：SceneInfo 里任何可读的量（关节角度、物体位姿、接触、时间、抽象体）。
- **规则**：
  - 比例映射；
  - 阈值开关（带状态，如“已按过”）；
  - 延时或渐变；
  - 沿路径、区域内游走；
  - 项目里的 Python 函数。
- **去向**：只有两类写入口：
  - 关节驱动的目标位置或速度（门、抽屉、升降台）；
  - 运动学实体或抽象体的位姿。

分成两层，界面上放在一起：

| 层 | 包含 | 执行方式 | 范围 |
|---|---|---|---|
| 物理关系 | 联动、固定连接 | 引擎在每个物理子步保持，力双向传递 | 同一物体内，或已固定连接的物体之间 |
| 逻辑关系 | 触发、运动及其余 | 每个决策步算一次，单向 | 可跨多个物体，可带状态 |

- **配置**：scene.yaml 顶层 `behaviors:` 列表，每条写明来源、规则、去向；复杂规则引用项目函数。
  旧的实体 `motion` 照样能读，作为来源是时间的内置规则。
- **执行**：`shared/assembly` 里的公共执行模块，由现在的 `motion.py` 扩展而来。
  每步在复位之后、观察之前运行，按环境批量计算，状态随复位清零。
  各后端只提供两个写入口：关节目标和位姿。Task 和 Policy 都不涉及。
- **check 时校验**：
  - 两条关系写同一个去向（冲突）；
  - 去向关节没有驱动；
  - 写了受力物体的位姿；
  - 单位或维度不符。

## 交互

1. **句子卡片**（主要编辑方式）：右栏“行为”区，每条一张卡片，空格都是下拉或数值框。例如：
   - 当【按钮·按下深度】大于【3 mm】时，【门·铰链】转到【1.5 rad】，否则回到【0】
   - 【指针】=【−0.5】×【旋钮】
   - 【平台】沿【路径 A】往返
2. **3D 连线**：选中物体时画出与它相关的关系，物理联动用实线，逻辑触发用虚线箭头。
   支持从一个物体或关节拖到另一个来新建关系。
3. **编辑器内试运行**：拖动来源，去向按规则即时响应；时间类规则可以播放。
4. **节点图总览**：以后再做，先只读。数据始终只有 scene.yaml 一份。
